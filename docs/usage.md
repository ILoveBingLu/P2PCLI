# 使用说明

## 本机

左侧最上面的“本机”是这台电脑自己：点它展开就能在本机开终端、接回后台会话，多标签、后台会话、命令行 AI 的状态识别都和连远程设备一样，不经过网络，也不用配对和同意。本机的终端标签底部显示“本机”，关掉标签不影响它。本机没有 tmux（Windows 是 psmux）时，新开的是普通终端，能用，只是关了软件就没了。手机、别的电脑连到本机开的会话也列在“本机”下面，标着“来自 xx”，点一下就在这台电脑上接着用，不用一直守着开它的那台设备；两边可以同时开着，看到的是同一个终端。

## 设备在线状态和会话列表

打开软件后，左侧连接历史里的设备会自动显示在不在线、延迟多少（不弹窗、不算一次连接；延迟每 2 秒刷新，对方断网或关机几秒内显示离线），对方同意过一次的设备还会直接列出你开在它上面的会话（只有编号和状态），点会话就连上并打开；离线时显示上次看到的会话。被连方可以在 设置 → 受信设备 里管理这些配对过的设备。对方的 P2PCLI 也要是新版本才有延迟和会话列表，旧版本显示“需更新”。

## 局域网

同一个局域网里的电脑不用设备码：打开软件后会自动出现在左侧“附近设备”里，点一下就连（还是要配对密码和对方同意，受信设备直接连上）。连接历史里的设备在局域网里在线时会标“局域网”，从那里连也不经过牵线服务器，外网断了也能用。访客 Wi-Fi、开了设备隔离的网络互相看不到，照常用设备码；Windows 第一次打开时防火墙询问要允许，网络被设成“公用网络”时可能也看不到。不想让同一网络里的人看到本机，在设置里关掉“在局域网中显示本机”。

## 互相信任

连接时勾选“互相信任”，连上的同时把对方记成本机的受信设备，对方以后可以直接控制本机，不用密码也不用点同意（它上面的命令行 AI 就能直接操作本机），可以在 设置 → 受信设备 里随时移除。没勾的话，只要本机成功连过对方，对方反过来连本机时就不用输配对密码，只在本机弹窗问你；窗口没在前台时还会发系统通知。弹窗里点拒绝或没人点，30 秒内同一台设备再来也直接被拒，不会反复弹窗。没互相连过的设备照旧要配对密码。

## 被连的一方

被连方标题栏右边会一直显示谁正在用本机终端，点开能看是谁、开了几个终端、连了多久，随时可以断开。弹窗里勾选以后不用确认的设备，下次连过来免密码免弹窗，只建议给自己的电脑勾。关掉窗口软件会留在托盘，别人照样能连进来。

## 切换目录

终端底部栏左边是会话当前所在的目录，点开是那台电脑上的目录列表：单击进入子目录，上方可回上一级或用户目录，输入文字筛选，方向键加回车也能选；选好后点“切换到这里”（或 ⌘/Ctrl+回车），终端就会 cd 过去。只有终端停在空闲提示符时才能切换，跑着程序或命令行 AI 时只能浏览，免得 cd 被当成输入发给程序。两边都要是支持该功能的新版本，对方版本太旧会提示更新。

## 代码编辑器

终端右侧悬浮条里的代码图标（或目录列表里的“在编辑器中打开”）会打开一个单独的编辑器窗口，直接改对方电脑上的文件，不用来回传。左边是对方电脑上的文件树，右边是和 VS Code 同款的 Monaco 编辑器，语法高亮、查找替换、多光标都有。编辑在本机内存里进行，只有打开和保存时各走一次网络，跨境高延迟也不影响打字；⌘/Ctrl+S 保存。保存时会核对文件在对方电脑上有没有被改过（比如被终端里的 AI 改了），改过就提示用对方的版本还是用自己的覆盖，不会悄悄盖掉；没改动的文件切回来时会自动换成对方电脑上的最新内容。保留 UTF-8 BOM 和原来的换行符，原地写回，文件权限和符号链接不变。二进制文件、非 UTF-8 编码（如 GBK）和超过 5 MB 的文件不在编辑器里打开。连接断开时打开的文件和未保存的修改都会保留，重新连上后接着保存。每台设备一个编辑器窗口，再点一次就把它叫到前面；终端里点文件路径也会在这个窗口里打开。窗口标题前的 ● 表示有没保存的文件，关窗口前会提醒。关掉这台设备的最后一个终端标签会断开连接，编辑器窗口里的修改保留，重新连上后自动接上。编辑器组件第一次打开时才加载，不拖慢启动，安装包增加约 3 MB。两边都要是支持该功能的新版本，权限和开终端一样，不额外放权。

编辑器里还能：⌘/Ctrl+P 按名字找文件（文件列表打开时取一次，之后在本机筛选，打字不等网络）；⌘/Ctrl+Shift+F 在对方电脑上搜整个目录的文件内容，支持区分大小写、全字匹配和正则，点结果直接跳到那一行，会跳过 .gitignore 里的文件、.git 目录、二进制文件和超过 2 MB 的文件；在文件树里右键新建文件或文件夹、重命名、移到废纸篓（删除的东西进对方电脑的废纸篓或回收站，可以找回；改名不会盖掉已有的同名文件）、复制路径、以某个文件夹为根目录。编辑器开着时每 3 秒看一眼对方电脑上的变化：没改过的文件自动换成最新内容，有未保存修改的文件马上提示（可以先对比再决定），被删掉的文件会标出来，保存时可以重新创建；文件树也跟着刷新。在 Git 仓库里时，文件树和标签用颜色标出改过（M）、新加或未跟踪（U）、有冲突（!）的文件，底部显示当前分支，改过的文件可以和 Git 最新提交里的版本左右对比，对比时也能接着编辑。看 Git 状态时不占用仓库的 index 锁，不影响终端里的 git 命令；对方没装 git 时这部分不显示。

代码补全、跳转和报错：打开 Rust、Go、Python、TypeScript/JavaScript、C/C++、Swift 等文件时，P2PCLI 在对方电脑上启动这种语言的语言服务（rust-analyzer、gopls、basedpyright/pyright、TypeScript 7 自带的语言服务或 typescript-language-server、clangd、sourcekit-lsp 等），经 P2P 连接把补全、悬停说明、函数参数提示、跳到定义（F12，能跳到别的文件）、查引用、高亮同名符号、格式化和报错波浪线带到编辑器里，看到的是整个项目的类型和依赖，不只是当前文件。语言服务按对方终端里的 PATH 找，也会看 Homebrew、Xcode 命令行工具和 VS Code/Cursor 插件自带的 rust-analyzer，不用另外配置；同一个项目（比如 Cargo 工作区）的文件共用一个语言服务。状态栏显示它的状态（启动中、索引进度、出错）；对方没装时显示“无补全”，提示里写着怎么装，装好后点一下重试。编辑器关掉或断线时，语言服务和它启动的检查进程一起结束。

还有：左边的“问题”列出语言服务报的整个项目的错误和警告（没打开的文件也算，比如 rust-analyzer 跑 cargo check 发现的），点一条跳过去，⌘/Ctrl+Shift+M 打开，状态栏也显示错误和警告数；F2 重命名符号、⌘/Ctrl+. 快速修复（自动导入、按提示修改等），涉及的文件会在编辑器里打开、改完标成未保存，确认后点“全部保存”（⌘/Ctrl+Alt+S）一起保存，保存时照常检查对方电脑上的文件有没有被改过；⌘/Ctrl+Shift+O 跳到当前文件里的函数，⌘/Ctrl+T 在整个项目里按名字找函数和类型。终端里编译报错、AI 输出中的文件路径（比如 src/main.rs:42:5、main.ts(12,3)、Python 回溯里的文件），按住 ⌘/Ctrl 点一下就在编辑器里打开并跳到那一行，相对路径按终端当前所在目录算。

Git 面板：编辑器左边的“Git”（⌘/Ctrl+Shift+G）列出暂存的和没暂存的改动，可以逐个或全部暂存、取消暂存、放弃修改（没跟踪的新文件移到废纸篓），点改过的文件和最新提交对比；写好提交说明按 ⌘/Ctrl+Enter 提交（没有暂存时问一下再全部暂存）；还能推送、拉取（只快进，有分叉时提示去终端里处理），看领先和落后上游几个提交、最近的提交记录。命令都在对方电脑上跑，用那边的 git 配置、账号和提交钩子；需要输入密码时会直接报错，不会卡住。编辑器里还有没保存的文件时，提交前会提醒。

## 端口转发

对方电脑上跑着开发服务器、接口或数据库后台时，点终端右侧悬浮条里的端口按钮，能看到对方电脑上正在监听的端口和程序名，一键转发到本机并用浏览器打开；也可以手动填端口。终端里开发服务器打印的 http://localhost:5173/ 这类本机地址，按住 ⌘/Ctrl 点一下就会自动转发并打开。本机端口尽量和对方一样，被占用时换一个并提示；手动转发时也可以在“本机端口”里指定一个。转发的端口只在本机（127.0.0.1）能访问，经 P2P 加密传输；对方只连它自己的 localhost，不会被当成进入它局域网的通道。

转发不跟着终端标签走：关掉标签、网络断了，本机端口都一直听着，下一个连接进来时自动重连对方（和命令行 `p2pcli exec` 一样用连接历史里的认证，对方没勾受信时会弹窗问它）；在面板里点停止才停。正在转发的设备旁边有个插头图标。点转发旁边的图钉“记住”，本机端口就固定成现在这个，下次打开 P2PCLI 自动恢复：先在本机端口上听着，有连接进来才去连对方，所以对方不在线也不会一直重试。本机端口被别的程序占着时，转发下面会提示，过几秒自动再试。记住的转发存在 P2PCLI 数据目录的 `forwards.json` 里；停止转发就一起忘掉。

不开终端标签也能用：在左侧设备上右键选“端口转发…”，没连上的设备会先连上。面板最上面写着当前线路；走中继时会提示比较慢（见下面的“直连优先”）。

反向端口转发：反过来把本机的端口接到对方电脑的 127.0.0.1 上，对方电脑上的程序连那个端口就连到本机，比如让对方回调本机正在调的接口。在端口转发面板的“反向转发（本机 → 对方）”里填本机端口（或 主机:端口）和对方端口（不填就随便挑一个空闲的）。

把本机代理借给对方（借网）：对方没有代理、上不了外网时，在左侧设备上右键选“把本机代理借给这台设备”，或者在端口转发面板最下面点“借给对方”。用的是 设置 → 代理设置 里填的代理，没填就试 `127.0.0.1:7890`；写 `socks5://` 开头按 SOCKS5。之后在对方电脑上新开的终端、后台会话和远程执行的命令会带上 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`（还有 `NO_PROXY=localhost,127.0.0.1,::1`），走本机的代理；已经开着的终端不受影响，也不改对方系统的代理设置。借着的设备旁边有个地球图标，右键可以停。注意：对方电脑上别的程序也能连到这个端口，等于也能用你的代理。关掉终端标签不会停（连接为它留着），连接真的断了才自动停，借网不会自动恢复。两边都要是 0.1.19 以上的版本；老版本 tmux（3.2 以前）新建的后台会话不带代理。

## 用本机 VS Code 打开（SSH）

在左侧设备（Mac、Windows、Linux）上右键选“用本机 VS Code 打开…”，在对话框里浏览对方电脑上的文件夹（单击进入子文件夹，可以筛选，也能直接改上面的路径；从上次打开的位置开始，第一次是用户目录），选 VS Code 或 Cursor，点打开。编辑器用它的 Remote-SSH 连过去，所有扩展、调试、终端都和平时一样；SSH 走 P2PCLI 的加密通道（`p2pcli pipe`），不用对方开公网端口、不用跳板机。本机编辑器要装 Remote-SSH 扩展，命令行工具 p2pcli 要装好（设置 → 文件传输）。

- 对方是 Mac、Linux：不用开系统的“远程登录”，也不用密码。对方的 P2PCLI 以当前用户的身份另起一个只听本机回环的 sshd，配置、主机密钥和授权的公钥都放在它自己的数据目录里，不碰 `/etc/ssh`；本机的 P2PCLI 替你管一把密钥（数据目录下的 `ssh/id_ed25519`），连的时候把公钥交给对方记下。两边都要是新版本。
- 对方是 Windows：要先装好“OpenSSH 服务器”（设置 → 系统 → 可选功能）并启动 sshd 服务，登录按 Windows 的方式（密码或你自己配的密钥）。
- 第一次用时会问你能不能在 `~/.ssh/config` 最前面加一行 `Include ~/.ssh/p2pcli_hosts`，原有内容不动。P2PCLI 只维护 `~/.ssh/p2pcli_hosts` 这一个文件，每台设备一个别名（`p2p-设备名`），终端里也能直接 `ssh p2p-设备名`。ssh 不记这些别名的主机密钥（第一次连不用确认指纹，对方从系统的 SSH 服务换成 P2PCLI 起的那个也不会报主机密钥变了）：对方是谁由 P2PCLI 的连接认定，SSH 服务只听对方电脑自己的本机回环。
- Windows 上 P2PCLI 写的这两个 SSH 配置文件只留本人、SYSTEM、Administrators 的权限：Windows 版 OpenSSH 见到别的用户或组的权限会拒绝读配置。

## 远程控制

对方是 macOS 或 Windows 时，点左侧的设备，右边设备页的标题栏有“远程控制”按钮；也可以在左侧设备上右键选“远程控制”，没连上的设备会先连上。点开是一个单独的窗口，能看对方的屏幕，也能用键盘鼠标操作它；窗口开着时，关掉这台设备的终端标签也不会断开画面。抓屏、编码、解码全用两边电脑的显卡：macOS 用 ScreenCaptureKit 抓屏、VideoToolbox 硬件编码，Windows 用 Windows.Graphics.Capture 抓屏、显卡的编码器（NVENC、Quick Sync、AMF）。两边显卡都支持 H.265 时自动用 H.265（同样码率画面更清楚，同样清晰度省三到五成流量），有一边不支持就用 H.264；两边显卡还都支持 H.265 的 4:4:4 档次时（比如被看的是装 NVIDIA 显卡的 Windows、看的一方显卡能解），用真正的 4:4:4，每个像素都有自己的颜色，彩色小字更清楚，不支持就是普通的 4:2:0（Mac 的硬件编码器没有 4:4:4），连接详情里的「色彩」按实际解出来的显示；画面从抓下来到编码完一直在显存里；看的一方用 WebCodecs 交给显卡解码，几乎不占 CPU。工具栏能换屏幕（多屏时）、换画质（清晰是原生分辨率，Retina、4K 屏按实际像素传，两边都用 H.265 时 5K、6K 屏也不缩小，用 H.264 时长边最多 3840；均衡长边 1920；流畅 1280、30 帧）。帧率跟着两边的屏幕走，取两边屏幕刷新率里小的那个，不另外封顶：两边都是 144 Hz 就是 144 帧（Windows 被看时要 Windows 11 24H2 或更新的版本才能超过 60 帧），能在“操作”和“只看”之间切换，能全屏。键盘按键位发送，用什么输入法、什么键盘布局都不影响，对方按它自己的布局出字；Mac 和 Windows 互相操作时，快捷键默认按本机的习惯来，对方自动换成它的按法：不是一个个快捷键查表，而是按修饰键的用途换——⌘ 和 Ctrl 都是命令键（复制、保存、新标签……所有程序都跟着对）；在文字里移动光标也跟着换（Mac 的 ⌘←/⌘→ 到行首行尾、⌥← 按词跳，对应 Windows 的 Home/End、Ctrl+←）；Mac 的 ⌘Q 和 Windows 的 Alt+F4 互换；Mac 上单按 ⌘ 是 Windows 的开始菜单，⌃ 点击是右键。对方 Mac 的前台是终端时，Windows 的 Ctrl 还是 Ctrl（Ctrl+C 中断），复制粘贴用 Ctrl+Shift+C/V。工具栏上的键盘按钮可以关掉，改成按键原样发送（两边都要是新版，对方是老版本时只对调 ⌘ 和 Ctrl）。系统自己先拦下的组合键（Mac 的 ⌘Tab、⌘空格，Windows 的 Alt+Tab、Win+L）到不了对方。码率按网络自动调，网差时先降清晰度、不越积越卡；屏幕不动时不发数据。操作时工具栏还有两个按钮：「送文字」用本机的输入法打一段字直接送过去（对方没装中文输入法也能输入，回车发送）；「锁定鼠标」把鼠标锁在画面里、只发移动量，第一人称游戏转视角要用它，按 Esc 解锁。把文件拖进画面窗口就发给这台设备，发完提示存在对方电脑的哪里。连接详情里能看到对方用的编码器（显卡硬件编码还是软件编码）、延迟估计和首帧用时。

画面只走直连（IPv6、IPv4 打洞、局域网），不走中继：中继只给终端这种小流量用。连接落到中继上时画面暂停，窗口里写明原因，终端照常能用，直连恢复后画面自动接着放。

剪贴板互通：操作对方电脑时，两边的剪贴板是通的。文字、带格式的文字（HTML、RTF）、图片、文件和文件夹都能复制过去粘贴，不限大小；两边都是 Windows 或都是 Mac 时，Excel、Office 这类程序自己的格式也原样带过去。复制时只把“有什么”告诉对方，小段文字顺带过去，大内容和文件在真正粘贴时才传，不会白传，也不挤画面。Windows 上粘贴对方的文件走“虚拟文件”：资源管理器、Outlook 能粘，边收边写、有进度；只认真实文件路径的程序（比如部分聊天软件）还粘不进去。Mac 上粘贴对方的大文件时会先传到临时文件夹，传完之前 P2PCLI 会暂时没有响应。只看不操作时不互通，画面窗口工具栏上的剪贴板按钮可以关掉。两边都要是 0.1.18 以上的版本。

被看的一方：受信设备直接打开，别的设备要在弹窗里点允许，可以只让看、不让操作。对方的 AI 用 MCP 截屏（`p2p_screenshot`，见 [命令行工具 p2pcli](cli.md)）时也是一样：弹窗问你，受信设备按设置直接放行，截完会发系统通知。有人在看时标题栏右边一直亮着，点开随时停止。设置 → 远程控制 里能关掉这个功能，或者只允许看。macOS 第一次要在 系统设置 → 隐私与安全性 里给 P2PCLI 打开“录屏与系统录音”（看画面）和“辅助功能”（操作键鼠），设置页里有按钮直接跳过去；录屏权限打开后要重开 P2PCLI。Windows 不用另外授权，但以管理员身份运行的窗口、UAC 弹窗和锁屏界面收不到远程的键鼠操作，这是系统的限制。Linux 暂时只能看别人，不能被看。两边都要是支持远程画面的新版本。

## 直连优先，中继兜底

连接总是先走直连（IPv6、IPv4 打洞、局域网），实在打不通才走中继；直连一接通就立刻从中继切过去。中继带宽小、延迟高，只保证“打不通也还能用”。所以流量大、时间长的事情开始前，如果连接还在中继上，会先等几秒直连：传文件、远程控制时粘贴大内容和文件、端口转发、反向转发、借网、SSH 都是这样，等不到才走中继，并在界面上提示会比较慢（传文件的卡片上写“经中继，较慢”，端口转发面板里写当前线路，远程画面窗口里弹提示）。远程画面只走直连。

## 连接详情

终端底部栏右边是这条连接的线路和延迟，点开是连接详情：网络延迟、按键回显（敲一个键到屏幕上出现字的时间，对方程序在刷屏时不测）、上下行带宽、丢包率；走的是 IPv6 直连、IPv4 直连还是中继，两头的地址；对方的软件版本、系统和会话管理器（tmux、psmux）。打开时每秒刷新一次，关着不统计。对方的版本和系统要两边都是 0.1.5 以上才看得到。

## 传文件

- 在左侧设备上右键选“发送文件”或“发送文件夹”；或者把文件拖进某台设备的终端窗口，发完会把文件在对方电脑上的路径填进终端，在那边跑的 claude、codex 直接就能读
- 收到的文件放在 `下载/P2PCLI/<发送设备名>/` 里（设置 → 文件传输 里能换文件夹），重名的自动加编号，不会覆盖。配对过的设备、自己连过的设备发来的直接收，别的设备发来要点同意
- 并发分段：文件切成 8 MiB 一段，最多开 8 条流一起发，每段各带 BLAKE3 校验，校验通过才算收好，断了再发会跳过已经收好的段。对方是旧版本时自动退回一条流。跨境这类高延迟、丢包的链路上能快一倍到几倍，传输面板里会显示实时速度和几条流并发
- 每个文件传完用 BLAKE3 核对；传到一半断了，再发同一批会从断点接着传
- 直连优先：开始前连接还在中继上的话先等几秒直连；走中继时传输卡片和命令行进度上写“经中继，较慢”，直连接通后提示消失
- 两边都要是 0.1.3 以上的版本

命令行里传文件、在对方电脑上跑命令见 [命令行工具 p2pcli](cli.md)。

## 认会话里的 AI

普通终端停在空提示符时，底部会浮出这台被控电脑已安装 AI 的启动胶囊，点击就在当前目录启动；输入命令或进入其他程序后隐藏，回到空提示符再显示。检测结果会缓存，旁边的刷新按钮可以重新检测。检测和启动都在被控端完成，双方需更新到支持启动器的版本；未知的自定义提示符会保守隐藏胶囊。

默认按 AI 自身的权限设置启动。右键 Claude Code 胶囊可以选择“启动并允许之后切换全部放行”（实际追加 `--allow-dangerously-skip-permissions`），只增加该模式的可选入口，不自动进入全部放行。

设置 → AI 启动 里可以给本机检测到的每种 AI 单独配置默认启动命令，支持完整路径、环境变量和参数；留空恢复自动检测到的命令。配置只保存在被控端本机，连接方不能上传命令，保存后立即用于之后的启动。若明确需要 Claude Code 启动后跳过工具确认，可以把它的命令设为 `claude --dangerously-skip-permissions`，之后普通点击胶囊也会全部放行；只应在可信项目中使用，它不改变操作系统权限，也不等于 `sudo`。自定义命令会交给本机 Shell 执行，不要在命令里保存令牌或密码。

远程会话里跑着命令行 AI 时，侧边栏、终端标签和底部状态栏会显示它的图标和状态：干活中、等你确认、空闲。忙碌画面连续 10 分钟没有变化会标成“可能卡住”，但不会被误判成空闲；长工具调用也可能暂时没有输出，需要到终端里检查。它停下来等你批准操作，或者干完活时，P2PCLI 会提醒你：窗口在后台发系统通知，在前台但没在看那个会话就弹提示，点“查看”切过去；正看着那个会话就不打扰。

- 认得：Claude Code、Codex、Antigravity CLI（谷歌接替 Gemini CLI 的新命令行 `agy`）、Gemini CLI、OpenCode、Cursor Agent、Copilot CLI、Qwen Code、Kimi CLI、CodeBuddy、Qoder CLI、iFlow CLI、Kiro CLI、Trae CLI、Amp、Aider、Crush、Droid、Goose、Auggie、ZCode（Z.ai 的 zcode-app-cli）。被连的电脑顺着会话的进程往下找，看程序名和完整命令行（Node、Python 写的 AI 程序名是 node、python，要看脚本路径），新出的在 `crates/core/src/agents.rs` 的表里加一行
- 状态：读会话标题和屏幕最后几十行判断，比如屏幕底部有编号选项和“Enter to confirm”就是在等你，有“✻ Cogitating…”或“esc to interrupt”就是在干活。整屏内容只在被连的电脑上解析；对方收到 AI 类型、状态，以及能明确识别的确认菜单和请求摘要
- 各家改了界面文字时状态可能判断不准，规则也在 `agents.rs`，测试里放着真实截下来的屏幕
- 额度：终端底部栏显示那台电脑上 AI 账号的额度，比如“5 小时 35% · 7 天 75%”，用到 90%、用满各提醒一次。Claude Code 读被连电脑上状态栏脚本存下的 `~/.claude/.statusline-ratelimits.json`（Claude Code 只把额度交给状态栏脚本，没配这样的状态栏脚本就读不到）；Codex 读 `~/.codex/sessions` 里最新会话日志最后一次记下的额度。只读本机文件，不联网、不碰登录凭据
- 输入框：看着跑 AI 的会话时，终端下面多一个输入框，在本机打完一整句再发过去，中文输入法选字不卡，长段落好改。回车发送，Shift+回车换行，输入框空着时上下箭头翻发过的话；文件拖到输入框上，传完把对方电脑上的路径填进来。⌘L（Windows 是 Ctrl+Shift+L）在终端和输入框之间切换，Esc 回终端，收起后按同一个键或输入框右上角的突出开关再打开。发送时按整段粘贴发过去，AI 不会把中间的换行当成回车；AI 在等你确认时不让发，免得一句话被当成选项
- 确认列表：Claude Code、Codex、Gemini CLI 的常见编号单选确认框，以及 OpenCode 的标准三项权限菜单，会浮在输入框上方，显示请求摘要和原始选项。被控端点击前重新核对屏幕、AI 进程和确认编号，再发送方向键与回车；同一确认只能提交一次。多选、自由输入、截断菜单、无法确定高亮项等情况保留终端操作，双方需更新。只传识别出的菜单及附近请求摘要，不上传整屏。
- 切模型、思考强度、权限模式：Claude Code 的会话在输入框右边有三个按钮。模型和强度照你在终端里打 `/model`、`/effort` 那样切，Claude Code 会顺带把它存成那台电脑上新会话的默认值（它自己的规矩，正在跑的其他会话不受影响）；权限模式只能 Shift+Tab 轮换，每按一下核对一次，到了就停，只改这个会话，“全部放行”要启动时加了 `--dangerously-skip-permissions` 才在轮换里。等你确认时都不能切，模型和强度要等它这一轮干完。当前值的来源：模型和强度读被连电脑上这个会话的对话记录（按 `~/.claude/sessions/进程号.json` 找到 `~/.claude/projects` 下的记录，设了 `CLAUDE_CONFIG_DIR` 就在那里找），刚开还没记录时读开头的横幅；权限模式读屏幕最底下那行。Codex 的模型列表随账号变，两个按钮打开它自己的 `/model` 和 `/permissions` 选择框。OpenCode 提供模型、思考强度、权限三个入口：模型打开 `/models`，思考强度打开 `/variants`（档位由模型和供应商配置决定），权限通过默认 Ctrl+P 打开命令面板并搜索 `permissions`，由用户在终端里确认开启或关闭自动批准，不会直接放行。按 OpenCode v1.19.4 核对；旧版若没有 variants 或自动批准入口需更新 OpenCode，自定义过 Ctrl+P 的用户仍可在终端自行打开命令面板。OpenCode 正在工作或等待确认时禁用这三个入口；当前选项在 OpenCode 自己的选择框中显示，不会把 Claude 的设置当成 OpenCode 的当前值。ZCode 也有这三个按钮，三样都从它最底下的状态栏读（`◈ 模型 ─ ◉ 模式 ─ ⚡ 强度`），能选的模型和每个模型的强度档位读被连电脑上的 `~/.zcode/cli/config.json`，只取模型名和档位，不碰里面的 key；切模型、强度发 `/model 提供方/模型`、`/effort 档位`，权限模式同样 Shift+Tab 轮换（build → edit → yolo → plan）。ZCode 自己的规矩：模型只改这个会话，强度会成为那台电脑上新开 ZCode 的默认值，权限模式会成为那个目录下的默认值
- 两边都要是 0.1.4 以上的版本；连着的设备每 4 秒更新一次状态
- AI 品牌图标是 [Lobe Icons](https://github.com/lobehub/lobe-icons)（MIT）的静态 SVG，放在 `app/src/assets/agents`，按图片显示，见那里的 LICENSE。不引 `@lobehub/icons`：它会带进整套 Lobe UI，新版本又常常刚发布、过不了 pnpm 默认的发布时间检查（24 小时内发布的包不装）。新增 CLI 时按 `agents.rs` 里的 kind 放一个同名 SVG；没收录的显示通用机器人图标

## 代理和网络设置

“连接设置”里的牵线服务器有“国内服务器”和“Cloudflare”两台可选，两台各自登记设备、互不相通：两边要选同一台才能用设备码互相找到，选的不一样就会报“没有这个设备码”；同一台电脑换一台牵线服务器，设备码也会跟着变，之前发给别人的码要重新发。国内外的人互连时，两边商量好用同一台（国内访问 Cloudflare 有时不稳）。

点击标题栏齿轮进入主区域的设置页，返回工作区时已有终端会话保持运行。“代理设置”分类中可启用 HTTP 代理，例如 `http://127.0.0.1:7890`（使用代理软件的 HTTP 或混合端口）。代理用于 WebSocket 牵线和 HTTP(S) 中继；UDP 牵线、点对点直连不经过该代理。暂不支持 SOCKS5、HTTPS 代理或账号密码认证，也不会自动读取系统代理。保存后即时应用，不必重启应用。设备名、牵线地址变更保留当前终端连接；代理或中继变更会重建网络端点，需重新连接远端，但后台终端会话继续运行。环境变量指定的服务器/中继仍优先于设置页。
